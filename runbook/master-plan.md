# 《明末 华夏震荡》上架游玩 · 执行总计划（我的版本）

> 本计划**完全重写**，不沿用上一任 `ai-context/master-plan.md` 的结论。区别一句话：
> 上一任证明"能跑、不崩、内容够"；本计划证明"**真的好玩、真的能上手、真的没坑**"。
> 依据：`assessment.md`。配套：`README.md`（入口 + 一句话启动 + 续跑协议）、`bug-ledger.md`（执行期维护）、`progress.md`（执行期维护）。

---

## 0. 目标与判据（一句话）

**把《明末 华夏震荡》做成"一个玩过 HOI4/EU4 的玩家打开就能上手、玩 1 小时不困惑、玩 10 小时不腻、不遇到 bug、愿意给好评"的浏览器游戏。**

"达标"的诚实定义（不再自指）：

- **AI 必须做到并给出证据**：真实游玩（浏览器自动化 + 截图 + 决策记录）跑通 8 势力完整循环；核心 bug 清零；平衡无 hack（详见 Phase 2）；事件决策有长期后果；文档与代码一致。
- **AI 无法替代、如实移交**：真人外测的"好不好玩"、美术/音频的"好不好看/听"、史实准确性。AI 不伪造这些结论，但要把验证材料备齐。

范围锁定：8 可玩势力 + 4 AI 势力、3 剧本、Web（Chrome/Edge 为主、Firefox 兼容）。**不新增内容量**（内容已够），除非 Phase 3 判定某处"重复到腻"才定向补。不做 Electron/Steamworks/i18n（沿用 `quality-bar.md` §4）。

## 1. 执行总原则

1. **先玩后改**：每个改动前先"自己玩一遍"复现，再改，改完再玩验证。headless 测试只作回归，不作"好玩"证据。
2. **证据驱动**：所有"好玩/平衡/体验"结论带截图或操作记录；数字落 `out/`（gitignored），结论写 `runbook/progress.md`。
3. **门禁纪律**：每个 Phase 结束必须 `pnpm typecheck && pnpm test && pnpm validate && pnpm audit:content && pnpm build` 全绿。
4. **迭代上限**：平衡/体验每项 ≤5 轮；超限停止并记录"未达标 + 原因"，不死循环。
5. **红线**（继承）：删除文件/目录、改密钥/CI、push、发布必须停下问用户；引擎不用 `Math.random`、不写 `any`；不引新依赖/后端/UI 库（除非修复必需且写明理由）。
6. **commit 纪律**：启动句含 commit 授权时，每 Phase 门禁全绿后提交一次（message 带 Phase ID，如 `feat(play): phase 2 real balance`）；**永不 push**。
7. **记录**：每 Phase 在 `runbook/progress.md` 追加：做了什么 / 证据 / 遗留 / 下一阶段入口。跨会话先读 progress 找续跑点。

## 3. Phase 0 — 真实基线（≤2 小时）

**目标：我不再只信文档，而是"亲自玩一遍"建立自己的基线。**

1. `pnpm dev` 起服务，用 `scripts/dev/e2e-ui.mjs` 或 Playwright 打开游戏，**以玩家身份**走一遍：选剧本 → 选势力 → 跳过引导 → 看开局清单 → 开国策 → 调分配 → 练兵 → 行军 → 宣战 → 议和 → 存档 → 读档 → 改设置 → 回主菜单。
2. 全程截图（`out/screenshots/`）+ 记录：每个屏幕我作为玩家"第一眼困惑"在哪、哪个数字不懂、哪个按钮点不动、哪一步卡住。
3. 挑 3 个差异最大的势力（明 / 郑 / 日本）各跑 15 分钟，记录真实差异。
4. 核对文档 vs 代码：逐条验证 `how-to-play.md` 里的数字与操作是否与当前实现一致，产出"过时文档清单"。
5. 产出 `runbook/bug-ledger.md` 初版（把我游玩中发现的 bug/UX 问题逐条记入）。

**验收**：`runbook/progress.md` 有真实游玩记录（截图路径 + 逐屏困惑点）；过时文档清单 ≥1 条；bug-ledger 有初始条目。直接进 Phase 1，不停顿。

## 4. Phase 1 — 真人视角 bug 猎杀

**目标：用真实游玩找出 headless 测试永远发现不了的 bug（UI 死路、误导文案、状态残留、真实崩溃）。**

1. **8 势力全循环**：每个势力按 Phase 0 的同一路径走一遍（浏览器自动化，断言 + 截图 + 记录），重点盯：
   - 读档后残留状态（上一任修过 BUG-035，需复查是否彻底）
   - 事件选项的"当前 → 预计"代价显示是否真实
   - 战争/和平/停战状态机在玩家视角是否自洽（宣战理由、白和、议和选项）
   - 面板空态、禁用按钮是否给出原因、危险操作是否二次确认
   - 胜利/灭亡/终局弹窗文案
2. **边界探针补充**：补单测覆盖 Phase 1 发现的每个 bug 的最小复现。
3. **修复回归**：每个 bug 走"复现→修复→回归"并记入 `runbook/bug-ledger.md`（ID/症状/根因/修复/测试）。删除文件类先问用户。

**验收**：阻断 0、严重（P1/P2）清零；8 势力全循环无 page error / console error / 横向溢出；新增回归测试；门禁全绿。

## 5. Phase 2 — 平衡去 hack（把纸面掩盖换成真机制）

**目标：移除上一任用 hack 掩盖的平衡问题，用真机制让平衡自然成立。**

1. **移除 `late.yaml` 的 `provinceCount < 200` 内容门槛**（这是饿死大国内容的体验 bug）。改成：晚期事件对大国也有（收益递减或代价上升），而不是直接屏蔽。
2. **1650 单极**：查清开局 60.6% 的结构，给反清势力（南明/郑/西/藩）一条**可玩的追赶路径**（联盟协同、海贸/藩属收入、清内部分裂事件），让 hard 之外的难度也能出现非清胜者。目标：1650 每难度 5 种子 ≥2 种胜者。
3. **囤银受控**：加硬 sink——国库超规模维护费随规模递增、通胀随银量上升、AI 把多余银投入军备/赈济/吏治（已有雏形，需加强）。目标：大国国库 ≤ 24 个月支出。
4. **重跑 45 局矩阵**（3 剧本 × 3 难度 × 5 种子）验证多胜者、无僵尸、无孤儿；结果固化进 `runbook/progress.md` 作基线。

**验收**：`late.yaml` 无 `provinceCount<200` 门槛；45 局多胜者（1650 不再单极）；囤银受控；无僵尸/孤儿；门禁全绿。未达标项 ≤2 且写明原因。

## 6. Phase 3 — 核心循环趣味性（"好玩"的最大杠杆）

**目标：让决策有可感知的长期后果、让 AI 像有想法的对手。**

### 6.1 事件决策链（优先，低风险高收益）

- 给每个可玩势力挑 3–5 条**关键历史事件**，加 `set_flag` → 后续条件事件 → 长线后果（例：明"催战出关"若失败，3 年后触发"潼关失守"连锁；选"招抚"而非"围剿"会在 2 年后得到火器工匠科技加成，但也埋下叛变隐患）。
- 事件选项不只 ±数字，要有"短期收益 vs 长期隐患"的取舍，且**后果在后续事件/修正里可见**。
- 用 `fire_once` + flag 确保不重复、不冲突；`pnpm validate` 校验 flag 引用。

### 6.2 AI 策略性（中等风险，需回归平衡）

- 兵力集中：多个军团朝同一战线会合，而非各走最近敌省（改 `manageMovement` 的 front 分配，让同势力军团共享目标优先级）。
- 反应式外交：被背刺/背盟的 AI 会记仇（降低关系、优先报复），而非只看当前关系阈值。
- 海军战略（可选项）：郑/清/荷/日按制海权决策——控制关键港口的优先级、封锁敌方港口；若实现成本过高则明确列为"已知限制"写入文档，不假装。

**约束**：任何 AI 改动**不得破坏 Phase 2 已固化的 45 局平衡基线**；改完重跑矩阵对比，差异必须可解释。

### 6.3 内容重复审计（沿用上一任方法，但换判定）

- 用 player-bot 或真实游玩记录统计 10 小时档的事件重复与后期可用池；只在"重复到腻"时定向补内容（记录理由），不为了凑数补。

**验收**：关键事件有 flag 驱动的长线后果（可演示）；AI 兵力集中/记仇可观察；平衡矩阵无回退；门禁全绿。

## 7. Phase 4 — UX 打磨 + 文档校准

**目标：真实手感，而非"无溢出"这种及格线。**

1. **首 5 分钟**：以 Phase 0 的"第一眼困惑"清单为准，逐条清零——让新玩家 10 秒知道"我是谁/目标/第一步"。
2. **信息架构**：关键数字（银/粮/兵源/稳定/天命/欠饷）都有 tooltip 解释来源；每个面板有"下一步该干嘛"的暗示，而非干巴巴的数字。
3. **空态/禁用/危险/代价**：全覆盖（上一任声称清零，但用我的游玩记录复核，找漏）。
4. **文档校准**：修 `how-to-play.md` 的过时数字与字面 `\n`；README/quality-bar/progress 与代码对齐。让新玩家读到的第一份文档是准确的。
5. **性能保持**：改动后跑 `perf.ts`，确认 tick 仍 <2ms、加载 <300ms。

**验收**：真实游玩 1 小时（至少 2 个势力）无"这按钮啥意思"的卡点；过时文档清单清零；性能无回退；门禁全绿。

## 8. Phase 5 — 诚实验收 + 移交

1. **全量回归**：五门禁 + 45 局矩阵 + 每剧本 1 局 67 年长局 + `invariant-probe`。
2. **诚实打分表**（写进 `docs/quality-bar.md` §5，但口径换成我的）：9 条逐项标"AI 已实测 / AI 无法替代"，不再把"可验证部分"当"达标"。
3. **最终报告**（`docs/final-report.md` 重写或新写 `runbook/final-report.md`）：逐项证据 + 数字 + 已知遗留。
4. **移交清单**：只有真人能做的——真人外测（附问卷/指引）、史实审读、美术/音频评审、发行决策；每项附 AI 已备材料。
5. 更新 `runbook/progress.md` 收尾；最终 commit（若授权）。

**任务完成判据**：8 势力真实游玩循环跑通且有截图/记录；核心 bug 清零；平衡无 hack（45 局多胜者）；事件有长期后果；文档=代码；移交清单完整。
