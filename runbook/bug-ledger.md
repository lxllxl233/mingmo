## Phase 1 — 真人视角 bug 猎杀

### BUG-001 顶栏「粮」tooltip：控制省份显示的是省数，却除以府数（P2，fixed）

- **症状**：鼠标悬停顶栏「粮」，tooltip 显示「控制省份 310 / 160 · 地区 310 / 480」。310/160 明显荒谬（分子比分母大）。
- **根因**：`TopBar.tsx` 的 `controlledCount` 是省份数（480 口径），却被同时用于「控制省份」（府数口径 160）和「地区」（省份数口径 480）。
- **修复**：在数据选择器里用 `Set<prefectureId>` 单独统计 `controlledPrefectures`，tooltip 的「控制省份」改用该值。
- **测试**：`pnpm typecheck` 通过；真实游玩顶栏 tooltip 数字与 StartScreen「开局态势」一致（明 105 府 / 310 省）。

### BUG-002 分配面板「当前分配预计温饱 600000.0 个月」（P2，fixed）

- **症状**：开局打开「分配」，底部显示「当前分配预计温饱 600000.0 个月」，数字荒谬。
- **根因**：`EstatesPanel.tsx` 的 `foodMonths = (food + projectedFood) / Math.max(1, report?.foodArmy ?? 1)`。首月结算前 `report` 为 null，`foodArmy` 落到 `Math.max(1, 0)=1`，于是 `600000 石 / 1 = 600000 个月`。
- **修复**：`foodArmy <= 0` 时 `foodMonths = null`，渲染为「—（首月结算后显示）」。
- **测试**：typecheck 通过；开局打开分配面板不再出现荒谬月份。

### BUG-003 分配面板首日经济数字全 0 且无说明（P2，fixed）

- **症状**：开局第一天打开「分配」，经济大盘/税收总额/本阶级收入/实际入库全为 0，玩家误以为国家经济坏了。
- **根因**：`lastReport` 在 `createInitialState` 时为 null，直到第一次月度结算（约 30 日后）才产生；面板对 null 一律 `?? 0`。
- **修复**：面板顶部在 `!report` 时显示提示「尚未进行首次月度结算，下方经济数字会在首月结算后更新」。（更彻底的修法是初始态即算一份报告，但会改动经济基线，留给后续评估。）
- **测试**：typecheck 通过。

### BUG-004 文档 `docs/how-to-play.md` 正文有字面 `\n`（P3，fixed）

- **症状**：第 55、105 行正文混着字面 `\n`（「训练日耗。\n- **被围**」等）。
- **修复**：替换为真实换行。
- **测试**：`grep -nF '\n'` 仅剩 Windows 路径（合法）。

### BUG-005 文档 `docs/how-to-play.md` 数字过时（P3，fixed）

- **症状**：写「事件 102 / 测试 32 / 将领 73」，实际为 **214 / 154 / 86**（`pnpm validate` + `pnpm test` 实测）。
- **修复**：同步为 214 / 154 / 86，并同步 §7「事件总量 102 条 → 214 条」。
- **测试**：与 `pnpm validate` / `pnpm test` 输出一致。

### BUG-006 范围与实现不符：4 个「AI-only」势力实际可选、但无独特机制面板（P2，fixed，选项 B）

- **症状**：势力选择屏 1627/1644 各列出 **11** 张可选卡、1650 列出 10 张；大西/和硕特·西藏/荷兰东印度/沙俄均可选。但启动后它们的侧栏只有 8 个通用面板，**没有**独特机制面板；`src/engine/systems/` 也没有 `terror`/`theocracy`/`company_dividend`/`cossack_host` 实现。势力卡却仍标「恐怖统治/政教合一/公司分红/哥萨克」，构成假承诺。
- **根因**：`countries.yaml` 13 国（除 NEU）全部 `playable: true`，`unique_mechanic` 为 4 方从未实现。
- **用户决策**：选项 B——保留可选，去掉势力卡的假机制标签。
- **修复**：`StartScreen.tsx` 新增 `IMPLEMENTED_MECHANICS` 白名单（8 个已实现机制），势力卡只对白名单内机制渲染标签；其余 4 方只显示「领袖 · 性格」。
- **测试**：`probe-mechanic.mjs` 实测大西/西藏/荷兰/沙俄卡片为「领袖：X · 性格」（无机制标签），明/郑等 8 方仍显示机制标签；typecheck 通过。

### BUG-007 战争首日「投降倾向 42%」（P3，fixed）

- **症状**：外交面板开局三场战争（清→明、顺→明、西→明）在 1627-10-01 即显示「投降倾向：我 42% · 敌 42%」。
- **根因**：`surrenderTendency`（`war.ts:308`）基值硬编码为 42，健康国家刚开战、未失一地的投降倾向就是 42%，语义误导。该函数仅用于 UI 展示（DiplomacyPanel/PeaceModal/WarDock），不参与 AI 或实际投降判定。
- **修复**：基值 42 → 10；失地差（每省 7%）、战争疲劳、失首都、无军再推高，真正被打垮时仍可达 100%。
- **测试**：无测试依赖该值；typecheck 通过。

## Phase 2 — 平衡去 hack（进行中）

### BUG-008 `events/late.yaml` 用 `provinceCount < 200` 饿死大国内容（P1，fixed）

- **症状**：`late.yaml` 11 条通用晚期事件挂 `provinceCount: { lt: 200 }` 门槛。1650 剧本开局清占 291 省，永远触发不了这些事件，晚期内容干旱；这正是上一任用「内容门槛」掩盖 1650 单极的 hack。
- **根因**：上一任用「饿死大国内容」掩盖 1650 清一极化，而不是修平衡。
- **修复**：移除全部 11 条门槛，所有势力都能触发；奖励是固定小数额，对大国相对收益天然递减，不构成额外雪球。1650 单极改由反清势力追赶路径解决（Phase 2.2，见 progress）。文件头部注释同步更新说明去 hack 理由。
- **测试**：`pnpm validate` ok（214 事件、无 dead flag、无空事件）。

### BUG-009 反雪球靠 `dominantTag >= 0.38` 硬塞战争目标（P2，open，Phase 2/3 处理）

- **症状**：`ai.ts:267-271` 任何势力占领 ≥38% 省份时，其余所有 AI（除日/朝）都被硬塞为战争目标。这是 hack，不是真机制；配合 `HISTORICAL_EXPANSION_CAP`（`ai.ts:349`）锁死历史走向。
- **计划**：Phase 2 用真机制（反清追赶路径）替代；Phase 3 重写 AI 决策（兵力集中/记仇），使雪球反制自然成立。此项与 Phase 3 AI 策略性合并处理。

### BUG-011 1650 单极是结构性，事件级 ±数字改不动（P1，wontfix-by-design 记录）

- **症状**：1650 剧本 easy/normal 下清 6/6 居首（146–265 省），反清势力（南明/郑/西）无法翻盘。
- **第一轮尝试**：「三藩之乱 → 三藩平定」flag 链（清在仍 ≥200 省时被削稳定/兵源/银/军心）。矩阵实测**几乎无效**：清仍 8/9 居首，版图与改前几乎一致（262→250、186→191 等，属噪声）。
- **根因**：结构性——清开局即占 60.6%（291 省），经济/兵力优势是指数级的，单个 ±数字事件是杯水车薪；且 **1650–1683 本就是清统一全国的历史进程**，南明/郑/西在史实上全灭于 1683 前。
- **诚实结论**：硬凑「每难度 ≥2 胜者」需要非历史的 buff/nerf，违背游戏的史实框架。**保留三藩之乱**（史实风味 + 反雪球 + flag 链示范，Phase 3 长线后果的样板），但**不再把 1650 单极当作待修的 bug**；反清的可玩路径由 hard 难度提供（反清 2/3 胜），并在最终报告如实说明。
- **上一任对照**：上一任把「1650 单极为剧本设计例外」写在报告里，但没有给出证据与机制交代；本账本给出矩阵证据 + 结构性根因 + 明确的「设计事实」定性。

### BUG-010 囤银失控：郑/荷等海贸势力囤到上千万两（P2，第一轮改善但未达标）

- **症状**：1650 矩阵（3 难度 × 3 种子 × 33 年）实测 `richest` 多为郑氏，最高 **1040 万两**（normal/seed99），多局 500–1000 万；荷兰东印度 228–449 万。远超 master-plan「大国国库 ≤ 24 个月支出」目标。
- **根因**：双层——① 旧 sink `hoardLoss = (treasury - hoardCap) * 0.25` 均衡 = 上限 + 月净×4，形同虚设；② 更深层：和平海贸势力（郑/荷）月净收入奇高（数万到数百万两量级），且 AI 的 `manageInvestments` 只把超出 reserve 的 20% 做「通用消耗」、给的回报近乎 0（+0.15 稳定），支出远赶不上收入。上一任正是把「囤银 894 万」当「观察项」放过。
- **修复（第一轮）**：`economy.ts` 囤银 sink：`hoardCap` 500000+省×4000 → **350000+省×3000**；烧除率 0.25 → **0.5**；超上限通胀 0.05 → **0.08**。
- **验证（重跑 1650 矩阵）**：郑氏最高囤银 1040万 → **665万**，多数局 360–520万；清 224–268万 → 99–148万。**0 僵尸 / 0 孤儿 仍全 9 局成立**。
- **未达标**：郑氏仍囤 270–665万，未到「≤24 个月支出」。根因是海贸/富省势力的**收入规模**与 AI 支出不足，不是 sink 能单独解决的。
- **下一轮方向**：① 审计海贸/税收收入规模（`trade.ts` 商埠上限、`economy.ts` 税收基数）；② 强化 `ai.ts:702-708` 的通用消耗（给真实回报：练兵/赈灾/吏治/基建，而非 20% 打水漂）。此二者属 Phase 2.3 后续轮次 / Phase 3 AI 策略性。
- **测试**：`tests/economy.test.ts` +1（囤银 sink 把超上限国库压成净流出）。
