## 0. 任务定义

**把《明末 华夏震荡》做到品质达到可上架 Steam 的水准（不实际上架、不做桌面端/手柄），优化体验，找出并修复游戏里的 bug，全过程由 AI 完成。**

「达标」的精确定义 = `docs/quality-bar.md` §2 的 9 条标准中，**AI 可验证的维度全部达标**；只有真人才能做的验证（外测招募、史实审读、美术听感）整理成「移交用户清单」，不伪造结论。

范围锁定：8 可玩 + 4 AI 势力、3 剧本、Web 版（Chrome/Edge 为主，Firefox 兼容）。
**内容量已达标**（200 事件 / 504 独特国策 / 480 真实地名 / 8 势力机制），本任务原则上**不新增内容量**——除非 Phase 4 的重复度审计证明长局存在内容干旱（那属于质量修复，允许补，且记录理由）。

## 1. 执行总原则

1. **先验证，后修改**：每步先跑探针/测试复现，再改代码，改完回归。
2. **每个阶段结束必须全绿**：`pnpm typecheck && pnpm test && pnpm validate && pnpm audit:content && pnpm build`。
3. **证据驱动**：平衡/性能结论必须带数字；矩阵结果落 `out/*.json`（gitignored），结论写进 `docs/qa-checklist.md`。
4. **并行化**：Bug 审查、矩阵跑批、探针用 subagents 扇出并行。
5. **迭代上限**：平衡调整每项 ≤5 轮；超限不再调，记录「未达标 + 原因」进验收报告，避免无限循环。
6. **工程红线**（继承自 architecture.md §7）：删除文件/目录、改密钥/CI、git push、公开发布必须停下来问用户；不引入新依赖/后端/UI 库/美术素材（除非修复必需且写明理由）；引擎不用 Math.random、不写 any。
7. **commit 纪律**：启动句若含 commit 授权（§8 模板默认包含），每阶段验收通过后提交一次（message 带阶段 ID，如 `feat(q6): phase 2 performance targets`）；永远不 push。
8. **记录**：每阶段在 `ai-context/session-log.md` 追加：做了什么 / 证据数字 / 遗留 / 下一阶段入口。跨会话续跑时先读 session-log 和 docs/progress.md 确定续跑点。

## 5. 分阶段详细步骤

### Phase 0 基线复验（≤1 小时）

1. 读 `ai-context/session-log.md`（上次续跑点）、`docs/progress.md`、`docs/qa-checklist.md`。
2. 跑门禁 5 连：typecheck / test / validate / audit / build；跑 `pnpm exec tsx scripts/dev/perf.ts` 记录 tick 与加载数字。
3. 数字追加进 session-log；确认无未提交的半成品改动（有则先收尾或记录）。
4. 直接进入 Phase 1，不停顿等确认（用户已授权全程自动）。

### Phase 1 Bug 猎杀与修复

**1.1 引擎静态审查（并行 subagents）**：派 5 个审查代理，各自深读一块代码并产出「可疑 bug 清单」（文件:行 + 复现路径 + 严重度）：
- A：economy / crisis / tax / buildings / trade（财政闭环：月结、欠饷、危机、建筑效果）
- B：military / siege / naval / training（战斗、围城、水战、补给、补给上限）
- C：war / diplomacy / vassals / league / tribute（战争状态机、和平、联盟、朝贡、反雪球）
- D：events / triggers / effects / focus / research / modifiers（事件链、条件、效果栈、国策科技生效）
- E：state / save / hash / initial / tick / clock（初始化、存档迁移、哈希、日期边界、ended 判定）

**1.2 不变量探针**：新建 `scripts/dev/invariant-probe.ts`，跑 3 剧本 × 5 种子 × 5 年，断言：无 NaN/Infinity、无负资源（银/粮/兵源/稳定等）、军队 tag 指向存活国家、无孤儿省、日期不越 1683 边界、事件选项非空、无重复事件 ID。并入 `pnpm validate` 或独立脚本，供后续每阶段回归。

**1.3 UI E2E 扩展**：扩展现有 `scripts/smoke-ui.mjs`（或新增 e2e 脚本）：8 可玩势力 × 开局 → 逐面板打开（国策/科研/阶级/军事/外交/贸易/朝贡 + 各势力专属面板）→ 训练军团 → 行军 → 事件弹窗选项 → 存档/读档 → 设置修改 → 主菜单。1280×800 下断言无横向溢出、无 console/page error。失败即修。

**1.4 修复与回归**：每个确认 bug：先写最小复现（单测或探针）→ 修复 → 回归通过 → 记录到 `ai-context/bug-ledger.md`（ID/症状/根因/修复/测试）。删除文件类修复先问用户。

**验收**：阻断 0、严重 <5；invariant 探针 3×5×5 全绿；tests 87 → ≥107（+20）；E2E 全绿；bug-ledger 完整。

### Phase 2 性能达标

**2.1 引擎 tick 优化（6.2ms → <2ms）**：用 `scripts/dev/perf.ts` 分段计时定位热点（优先查：`ai.ts` 763 行月度决策、economy/military 全表扫描、事件按日全扫 pending、supply 连通分量未缓存）。手段按优先级：索引/缓存 > 惰性计算 > 算法替换。每轮优化后跑 perf 探针记录数字。**注意**：优化不得改变任何平衡结果（用 5 年模拟 hash 对比优化前后，要求一致）。

**2.2 地图脏渲染（MapRenderer.ts）**：分层（省底色/边界/标签/军队/箭头），仅重绘变化对象；标签池化/复用，避免全量销毁重建；占领单省重绘 <16ms。纹理内存：标签用 BitmapFont 或降 resolution，目标 <150MB（用 Pixi 纹理计数探针验证）。

**2.3 React 性能**：TopBar/右栏高频订阅改 selector + `useShallow`；派生值缓存；单 tick React 提交 <4ms（perf 探针或 Performance API 验证）。

**2.4 加载与拆包**：内容加载 305ms → <300ms（解析/校验惰性化，先查 loader/parse.ts 热点）；vite manualChunks 把 content 拆成多块，消除 >500KB 警告；pixi chunk 无解（依赖体积），在验收报告中注明即可。

**2.5 8h soak**：把 `scripts/soak-ui.mjs` 时长参数调到 8 小时，**后台跑**（run_in_background），本阶段其它工作继续；完成后检查内存曲线（增长 <10%）与 console/page error。若内存持续增长，用 heap 快照定位后修复并重跑。

**验收**：perf 探针 tick <2ms（P99 <8ms）、加载 <300ms、占领单省重绘 <16ms；1080p 60fps（smoke 中 rAF 帧率采样）；8h soak 0 error、内存增长 <10%；build 无 >500KB 警告（pixi 除外并注明）；5 年模拟 hash 前后一致（性能优化零行为变更）。

### Phase 3 平衡与 AI 收尾

**3.1 数据先行**：跑 45 局矩阵（3 剧本 × 3 难度 × 5 种子，约 13 分钟），输出每局：最大势力占比、囤银榜、战争时长分布、事件触发统计。写入 out/ 并摘要进 qa-checklist。

**3.2 逐项调参（每项 ≤5 轮，改完重跑矩阵验证）**：
- 1627 清偏强：查清入关事件 + AI 目标权重 + 联盟阈值（38%）与清扩张节奏；目标：清多数种子 120–180 省，且存在非清胜者。
- 困难 1650 郑偏强：郑海贸收入/海军优势与陆上 AI 应对；目标 ≤180 省。
- 日本 123 省异常：锁国 AI 被卷入战争后的扩张失控；目标锁国日本 24–57 省。
- 后期囤银：硬性 sinks（宫室/官僚维护、国库超限惩罚随规模加码）或 AI 投资倾向；目标大国国库 ≤24 个月支出。
- 1660 后战争停滞：AI 和平阈值/新战争理由/疲劳衰减；目标 20 年局后 10 年仍有 ≥1 场有意义战争。
- 顺/南明存活率：1644 顺常先亡的问题（观察 39 年局长局中顺 149 表现好，普通 20 年局需确认）。

**3.3 平衡带宽锁定**：达标后把矩阵结果固化为 qa-checklist 的基线表，后续任何改动回归对比。

**验收**：45 局全无僵尸/孤儿；无势力 ≥50% 省份连续 2 年；每剧本 × 每难度 ≥2 种不同胜者（5 种子内）；无长期 0 国库 + 0 军心僵尸；战争 1–5 年可结束；大国囤银受控。未达标项 ≤2 且写入报告说明原因。

### Phase 4 长局验证与体验打磨

**4.1 脚本化玩家（替代 30h 人工通关）**：新建 `scripts/dev/player-bot.ts`——规则驱动的「拟人玩家」：开局选国策/科研、按预算调整税法与军队、主动宣战/议和（读战争分）、处理事件（按代价择优）、定期存档。对 8 个可玩势力各跑 1 局 1627→1683（或死亡为止）。断言：无死锁（ended 判定正常触发）、无 NaN、无卡死事件；输出每局日志（关键决策/转折点/死亡原因）供「核心循环 4 段目标」分析。**这是 AI 对「30 小时通关」的最佳替代，验收报告中如实注明方法学，不宣称等于真人试玩。**

**4.2 内容重复审计**：在 8 局长局日志上统计：同事件触发次数、后期（1650+）事件可用池、国策/决议余量；判定 10 小时档是否有内容干旱。有干旱 → 允许定向补内容（记录理由），无 → 维度 4 与 2 的 AI 可验证部分达标。

**4.3 UI 打磨清单**：逐项检查并清零——1280×800 文本截断（长地名/长事件标题）、空态面板（无军队/无盟友时的提示）、按钮禁用原因、危险操作二次确认、事件选项代价预览（delta）、tooltip 覆盖关键数值来源。用截图对比（out/screenshots）做视觉回归。

**4.4 测试补强（87 → ≥150）**：按系统补单测：diplomacy 动作、vassals、trade、tribute、league、sakoku 边界、southernMing 触发条件、save 迁移边界、victory 判定、clock 闰年/边界。

**验收**：8 局脚本通关完成、无死锁；重复度报告产出（干旱 = 0 或已补内容）；UI 打磨清单清零；tests ≥150 全绿；门禁 5 连全绿。

### Phase 5 最终验收与移交

1. **全量回归**：门禁 5 连 + 45 局矩阵 + 3 局 67 年长局（每剧本 1 局，看海）+ 8h soak 复核（若距上次 >3 天或期间改过引擎）。
2. **更新 docs**：quality-bar.md §2「当前」列与 §5 打分表逐条更新；progress.md 收尾；qa-checklist.md 固化最终证据。
3. **最终验收报告**（写入 `docs/final-report.md`）：9 条逐项「达标/未达标 + 证据 + 方法学说明」；已知遗留问题列表；性能数字终值；bug 修复统计。
4. **移交用户清单**（写入 `docs/handoff.md`）：只有真人能做的——招募 10 名新玩家外测（维度 1/2）、史实审读、真人听感/视觉评审、上架发行决策；每项附「AI 已备好的材料」（问卷、测试指引、打包构建）。
5. 更新 ai-context 三件套；最终 commit（若授权）。

**任务完成判据**：9 条中 AI 可验证维度全部达标；移交清单完整；最终验收报告存在且数字可复现。
