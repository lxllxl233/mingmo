# 分阶段施工提示词 · 甲申

> 每个阶段单独开一轮（或新会话）。把对应小节整段粘贴，并附上：
> **当前仓库状态**（`git log --oneline -10`、`pnpm test` 结果）+ **上一阶段验收结论**。
>
> 阶段之间**不跳步**。前一个阶段的「验收清单」没有全绿，不要开始下一个。
> 特别是：**M1 的税法没闭环，不要开始 M7 的十二势力内容。**

# M0 · 骨架

**目标**：一张能点、时间能走、档能存的空壳。
**周期**：1–2 轮。

### 提示词

```
实现 M0「骨架」，只做四件事：项目骨架、内容管线、地图渲染、时间与存档。

1. 项目
   - pnpm + Vite + React 18 + TypeScript strict（noUncheckedIndexedAccess、exactOptionalPropertyTypes）
   - vitest；脚本：dev / build / test / typecheck / validate / sim
   - 目录严格按 00-master.md 第 6.1 节；engine 不得 import react/pixi/dom

2. 内容管线
   - zod 定义 Province / Prefecture / Region / Country / Estate 五个 schema
   - YAML 加载器：读 src/content/data/**/*.yaml，失败时报「文件 + 字段路径 + 期望值」
   - 建索引：provinceId → object、region 分组、邻接表、country → estates
   - pnpm validate 可单独跑

3. 地图几何（重要：不要找真实 GeoJSON）
   - 写 scripts/gen-map.ts：输入 480 个省锚点（id + 经纬度 + 名称），
     用 Voronoi 生成多边形（d3-delaunay 或自实现），按共享边算邻接
   - 舞台限定东亚：经度 70–150、纬度 15–55；锚点先给 80 个真实地点
     （北京、山海关、宁远、锦州、沈阳、济南、太原、西安、洛阳、开封、襄阳、
      扬州、南京、杭州、武昌、成都、重庆、昆明、贵阳、桂林、广州、福州、厦门、
      澎湖、安平、汉城、江户、恰克图、雅克萨、腾越……），其余按地区均匀补点
   - 输出 src/content/data/map/provinces.geo.json
   - 渲染：PixiJS 8，滚轮缩放、拖拽平移、点选高亮 + 侧栏
   - 省份着色按 owner 的 tag 颜色；边界描边；静态层缓存为 RenderTexture

4. 时间与存档
   - engine：GameState + tick(state) => state，纯函数
   - 1616-01-01 起，日推进；四档速度（暂停/1x/2x/4x）
   - 存档：JSON + localStorage，含 version / seed / date / state / checksum(sha256)
   - 读档校验 version 与 checksum，不匹配给明确错误

不要做：经济、阶级、军队、国策、事件、外交、AI。
```

### 验收

- [ ] `pnpm dev` 打开，看到东亚地图（480 省），能缩放平移。
- [ ] 点击省份，右侧显示 id / 名称 / 地形 / 人口 / `dominant_estate`。
- [ ] 4x 推进到 1683-12-31，无报错，UI ≥ 50fps。
- [ ] 存档 → 刷新 → 读档，日期与省份归属完全一致。
- [ ] `pnpm validate` 全绿（邻接双向、府归属存在、人口总和合理）。
- [ ] `pnpm typecheck` 零错误，零 `any`。

### 常见坑

- Voronoi 边界出现极细长条 → 加 Lloyd 松弛 2 次。
- 经纬度直接投屏会变形 → 等距圆柱投影 + 固定缩放，别上 GIS 库。
- 每帧全量重绘 480 个多边形会掉帧 → 静态层缓存，只重绘变化层。
- 别把「府」画在地图上——府是数据层，不是几何层。

# M1 · 经济与阶级（本作最重要的一关）

**目标**：让「财政漏水」和「向谁征税」同时可被感知。
**周期**：3–4 轮。这一关没做透，后面全是空转。

### 提示词

```
实现 M1「经济与阶级」，严格按 prompts/01-design-spec.md 第 7 节与
prompts/02-content-spec.md 第 8 节。范围：

1. 数据
   - content/data/estates/_common.yaml：8 个阶级定义（key、名称、sensitivity、income_from）
   - content/data/estates/MING.yaml 与 QING.yaml：启用阶级、影响力、忠诚、income_share、特权、税法
   - content/data/tax_laws/*.yaml：先做 25 条通用税法（可直接抄 examples/estates-tax.yaml）
   - content/data/balance.yaml：所有系数
   - 每个府：田亩、人口、发展度、dominant_estate、阶级收入分配

2. 引擎（每月结算，顺序固定）
   - 聚合各府收入 → estate.income
   - 按税法算 gross / evasion / collected（公式见 01 第 7.6 节）
   - 入银库（silver_share）与粮库（其余折粮）
   - incidence：上调税率的阶级把负担转给目标阶级（忠诚与 unrest 双扣）
   - 忠诚漂移：loyalty += (习惯税率 - rate) × sensitivity × 20 + loyaltyDrift
   - 抗税：loyalty < 30 时实收打折；< 15 时进事件池
   - 支出：军饷 → 官俸 → 宗禄 → 赈灾 → 工程；不足进入欠饷
   - 灾荒（季度）、人口增长、白银流入、通胀、漕运
   - 全部纯函数，输入 state + 日期，输出新 state

3. 税法改革
   - command：tax.setLaw
   - 90 日改革期 + 180 日冷却 + 政治点成本
   - 改革期内该阶级征收效率 -20%
   - 完成后触发「阶级反应」事件（支持/阻挠/暴动）

4. UI
   - 顶栏：银 / 粮 / 人口 / 稳定 / 欠饷月数（红字告警）
   - 阶级面板：8 个阶级卡片，显示忠诚、影响力、税负、实收、特权、当前税法
   - 税法确认框：必须显示「预计影响」——士绅 -12 忠诚、农民 -6 忠诚、年增收 +48 万两
   - 财政面板：收入按阶级分项 + 支出分项 + 12 个月趋势
   - 悬停任一数字 → 来源分解 tooltip

5. 遥测
   - pnpm sim --years 70 --seed 42 --out out/
   - CSV 列：年、势力、银库、粮库、总人口、每阶级忠诚/影响力/实收、抗税次数、民变次数
   - 断言：无 NaN、无负人口、income_share 之和 = 1、财政分项之和 = 净收入
```

### 验收

- [ ] 1627 开局，大明月度净额为负，3 年内银库见底、欠饷 ≥ 6 月。
- [ ] 点「三饷加派」：农民忠诚 24 个月内从 30 跌到 15 以下，并触发民变事件。
- [ ] 点「清丈限田」：士绅忠诚下降，同时农民忠诚因转嫁下降（两个阶级都动了）。
- [ ] 士绅忠诚 20 + 影响力 40 时，士绅实收明显低于账面，UI 标注「抗税」。
- [ ] 税法改革期间效率 -20%，改革完成才恢复；冷却期内按钮灰显。
- [ ] 财政面板分项相加 = 净收入，误差 = 0（写测试）。
- [ ] `pnpm sim --years 70` 跑完，CSV 无 NaN，且至少一个阶级忠诚 < 20。
- [ ] 10 种子下，大明在 20–40 年内出现「银库 < 0 且欠饷 > 6 月」的比例 ≥ 80%。

### 常见坑

- `income_share` 之和不为 1 → 税基凭空多出或消失，一定要在加载期断言。
- 转嫁写成双向递归 → 无限循环。incidence 只允许一跳，禁止链式。
- 忠诚漂移用乘法 → 会在 0 和 100 卡死。用加法 + clamp。
- 税率改一次就立刻生效 → 玩家会疯狂微操。必须有改革期。
- 把阶级收入和府收入各算一遍 → 两套账对不上。只保留府 → 阶级一条聚合链。
- 抗税只扣钱不扣别的 → 玩家无感。抗税必须伴随事件、unrest、甚至民变。

# M2 · 军事与战斗

**目标**：两支军队能在图上走、打、围。
**周期**：2–3 轮。

### 提示词

```
实现 M2「军事与战斗」：

1. 单位与兵源
   - 营（battalion）最小；标（brigade）= 3–5 营，地图上移动的是标
   - 属性：兵力/组织度/训练/装备/火器率/机动/补给消耗
   - 兵种：冷兵步兵、火器步兵、骑兵、炮兵、水师；克制表见 01 第 9.3 节
   - 每个标记录 source_estate（军户/募兵/家丁/八旗/土司/雇佣）
   - 招募消耗对应阶级的人口与忠诚；欠饷先打击募兵，最后八旗

2. 移动
   - Dijkstra 求省间路径；每日按机动推进；地形消耗
   - 进入敌方控制省触发战斗
   - 补给：从补给源沿己方控制省 BFS；超补给上限则组织度衰减

3. 战斗（逐日）
   - 战场宽度按地形；火力阶段 + 冲击阶段；伤害分摊；组织度归零撤退；骑兵追击
   - 战斗详情记录每阶段贡献，UI 可展开
   - 同种子同指令结果完全一致（跑两次比较 state hash）

4. 围城
   - 城防 = fortLevel × 100；每日削减 = 攻城值 × 炮兵加成
   - 守方粮尽额外削减；城破后可选「劫掠 / 安民」，影响 devastation 与民心（并回写阶级忠诚）

5. UI
   - 军队图标 + 兵力条；点击显示编成、兵源阶级、补给、命令
   - 右键规划路线，显示天数与补给消耗
   - 战斗图标进入战斗详情

6. 测试
   - 同等兵力，火器步兵平原对冷兵胜率 > 55%；骑兵对炮兵 > 65%
   - 5 万明军围宁远（fortLevel 8），无炮兵 90 日不克；有炮 60 日内克
```

### 验收

- [ ] 能选军、右键移动、到达、遭遇、进入战斗。
- [ ] 战斗 3–15 日结束；败方撤退；追击造成额外伤亡但保留 ≥ 20%。
- [ ] 围城有进度条，粮尽加速；城破后「劫掠/安民」影响阶级忠诚。
- [ ] 同种子重跑，战斗结果完全一致（hash 相等）。
- [ ] 切断补给后组织度逐日下降，UI 有提示。
- [ ] 欠饷 6 个月后，募兵部队出现逃亡，军户部队较晚。

### 常见坑

- 逐日对每对相邻敌军结算 → 先聚合战区再结算。
- 组织度归零仍在场上 → 立刻移出战线，否则反复触发。
- 追击伤害无上限 → 会出现一战全歼，加「溃退方保留 20%」守卫。

# M6 · 外交与 AI

**目标**：八个势力能自己打一场 70 年的仗，并且会调税。
**周期**：3 轮。

### 提示词

```
实现 M6「外交与 AI」：

1. 外交
   - relation（-100~100）、条约（停战/和议/盟约/朝贡/通商/借师）
   - 宣战需 cb；议和需双方接受度；朝贡有保护义务
   - 招抚：对农民军/军阀，花银 + 给官，成功率由军心/财政/天命决定
   - UI：关系矩阵、和谈界面（条件勾选 + 接受度预览）

2. AI（战略层每 30 日，战役层每 5 日）
   - 评估威胁 → 选目标（生存/扩张/统一/经济/复仇）→ 预算 → 选国策 → 战争决策
   - **财政 AI**：每月检查收支；连续 6 个月赤字时按优先级行动：
     ① 降军费 ② 加征（挑忠诚最低、影响力最低的阶级）③ 改税法 ④ 借债
   - **阶级 AI**：忠诚 < 30 的阶级，优先减税或给特权；影响力 > 55 的阶级，优先打压
   - 战役层：前线判定、兵力集中、进攻阈值（局部优势 ≥ 1.5）
   - 性格：aggressive / defensive / opportunistic / mercantile
   - 禁止全图视野作弊；禁止隐形经济加成

3. 难度
   - 三档：历史 / 困难 / 地狱；只调 AI 决策质量与初始条件，不调 AI 收入倍率

4. 测试
   - 8 势力全 AI，1627 起 70 年 × 10 种子：不崩、无 NaN、无「0 省势力仍在行动」
   - 统计：大明灭亡年份中位数 1640–1655；清统一率 30–60%
```

### 每批验收

- [ ] 3 个势力各自 40+ 国策、30+ 事件、一套阶级配置、一套独特机制。

### 常见坑

- 「换皮」：只改名字和颜色，机制一样 → 必须有一个改变操作方式的系统。
- 小势力被一刀灭 → 给它们地形、补给、外交上的生存空间。
- 独特机制写成纯加成 → 必须有代价与反噬。
